# 기능 개선 Phase Plan

작성일: 2026-10-04 · 상태: 구현·자동 검사·portable HTML 빌드 완료. 브라우저에서 직접 여는 동작 확인은 실행 도구의 `file://` 보안 제한으로 미수행.

## 실행 기준

별도 요청 전까지 사용자 기능 실행과 동작 확인은 `doanbogo-web/portable/index.html`을 Chrome 또는 Edge에서 직접 여는 방식으로 한다. 소스 변경 후 `npm run build:portable`로 이 파일을 다시 만든다. `doanbogo-web/index.html`은 Vite 개발 진입점이므로 인수 검증 기준으로 사용하지 않는다.

## Phase 0 — 실행 기준과 저장 호환성

- README와 이 문서에 portable HTML 실행 기준을 명시한다.
- 기존 페이지별 진행선 1개씩을 배열 기반 선 데이터로 읽고, 변경 저장 시 새 형식으로 보관한다.
- 기존 노트의 위치와 내용을 유지하며, 새 노트는 상자 크기를 저장한다.
- `.doanbogo` 백업은 v3으로 내보내고 v1·v2 가져오기를 유지한다.

## Phase 1 — Pages Guide 다중 진행선

- PDF 위쪽의 `+` 버튼은 세로선을, 오른쪽의 `+` 버튼은 가로선을 가운데 위치에 추가한다.
- 페이지마다 방향별 최대 10개까지 추가하며, 도달한 방향의 버튼과 설정 추가 기능을 비활성화한다.
- 진행선 설정에서 활성 페이지의 선을 추가·삭제하고 각 선의 위치를 조정한다. PDF 위에서는 선을 직접 드래그한다.
- 표시·색상·두께·투명도는 방향별로 공유한다. 추가, 삭제, 이동은 페이지별 실행 취소·다시 실행에 기록한다.

## Phase 2 — Page Note 텍스트 객체

- 텍스트 도구로 PDF를 클릭하면 해당 위치에 편집 상자를 만든다. 별도 편집 팝업은 사용하지 않는다.
- 상자 안에서 여러 줄을 입력하고, 상단 손잡이로 이동하며 모서리 손잡이로 크기를 조절한다.
- 선택한 상자의 삭제 버튼과 Delete 키로 삭제한다. 상자 밖 클릭으로 편집을 확정하고 Escape로 현재 편집을 취소한다.
- 기존 500자 제한과 글자 색·크기 설정을 유지한다. 내용·위치·크기는 페이지 작업 데이터와 백업에 저장한다.

## Phase 3 — 숨김과 Page Management

- 숨긴 페이지는 일반 페이지 썸네일에서 제외하고 페이지 이동 시 건너뛴다.
- 상단 페이지 관리 창에서 숨긴 페이지의 썸네일을 개별 선택한다.
- 선택한 페이지 복구와 전체 복구를 제공하고, 복구 후 원래 페이지 순서로 일반 썸네일에 표시한다.
- 여러 페이지 상태는 한 번의 저장 트랜잭션으로 갱신한다.

## 완료 검증

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build:portable` 통과.
- v1·v2 백업에서 진행선과 노트의 기존 위치를 읽고, v3 내보내기·재가져오기에서 다중 선과 노트 크기를 보존한다.
- Chrome 또는 Edge에서 `portable/index.html`을 직접 열어 일반 썸네일 숨김, 개별·전체 복구, 진행선 추가 한도·공통 스타일·이동, 노트 입력·수정·이동·크기 변경·삭제와 실행 취소를 확인한다.
- 단일·분할 보기와 확대 상태에서 해당 동작을 확인하고, 구현·자동 검사·직접 실행 검증 결과를 구분해 기록한다.
