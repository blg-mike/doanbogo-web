# 진행선 직접 조작 개선 Phase Plan

작성일: 2026-10-08
상태: Phase 1~5 구현 완료. Phase 6 자동 검증과 portable 화면 스모크 확인 완료. 실제 드래그·Android 조작 검증은 남아 있음.
대상: doanbogo-web의 PDF·사진 Viewer
기준: 이번에 첨부한 진행선 기능 명세. 이전 DEFAULT/MARKER/ADJUST 설계 중 조정 모드 요구는 이번 명세로 대체한다.

## 목표와 범위

- 진행선 시작 → 즉시 생성 → 본체 직접 드래그 → 선택 시 끝 핸들 표시 흐름을 제공한다.
- 마커·길이 핸들·본체의 입력 대상을 분리한다.
- 카운터 연결은 선택 기능으로 두고, 같은 선을 두 번 움직여 단 간격을 맞춘다.
- PDF·사진 렌더, 필기, 기존 카운터 그룹·정확한 이력 복원은 기존 경로를 유지한다.
- OCR, 자동 차트 인식, 자유 회전, 좌표·간격 수치 입력, 앱/APK 이관·배포는 범위에 포함하지 않는다.
- 기존 다른 작업의 변경사항은 보존한다.

## 적용할 기본 결정

- 첫 생성은 활성 페이지에서 현재 보이는 영역의 중앙에 배치하고 폭은 페이지의 65%로 시작한다. 확대·Pan 상태에서도 첫 선이 화면 밖에 생기지 않게 한다.
- 본체 짧은 탭은 선택으로 처리한다. 선택하면 끝 핸들과 옵션이 보인다. 마커 생성은 옵션의 ‘마커 표시’로 명시하고 마커를 끄거나 지울 수 있다.
- 본체는 선택 여부와 관계없이 8px 이동 후 축을 고정한다. 마커와 끝 핸들은 X축만 처리한다.
- 현재 최소 길이 20%, 페이지별 주선 1개·참고선 최대 2개, 회전 후 화면 수평, 회전별 위치 호환을 유지한다.
- 기존선은 원본을 보관하고 연결된 가로선 → 첫 가로선 → 첫 세로선 순서의 호환 표시로 즉시 사용하게 한다. 기존선 선택 전환은 옵션에서 사용자가 요청할 때만 연다. 새 페이지에는 시작 전까지 선을 자동 생성하지 않는다.
- 같은 페이지를 두 패널에서 보는 경우 저장 데이터는 기존 페이지 단위로 공유한다. 드래그 중 임시 표시와 Gesture는 시작 패널에 고정하고, 최종 저장 후 두 패널에 반영한다. 패널별로 서로 다른 저장 선을 만드는 변경은 별도 결정 사항이다.
- 카운터 동작 시작 시 활성 패널·페이지·주선·연결 카운터 ID를 고정한다. 비활성·숨김 페이지의 연결선은 그 동작으로 이동하지 않는다.
- 숫자 직접 입력은 크기에 관계없이 위치를 유지한다. 보조 카운터의 값·설정·완료 이력은 기존 ‘메인 숫자만 보정’ 요구를 지킨다.
- −1/단 되돌리기는 기존 정확한 그룹 이력 조건을 유지한다. 허용된 −1에서 연결선도 복원하며 임의의 과거 상태를 만들어내지 않는다.
- 반복은 명시적인 차트 영역·반복 설정이 모두 있는 연결에만 적용한다. 신규 연결은 반복 OFF이고, 필요할 때 도안에서 영역을 지정하는 최소 옵션을 제공한다.

## Phase 1 — 즉시 생성과 직접 드래그

선행 조건: 없음.

- Footer 진행선 버튼을 시작/선택 진입으로 바꾼다. 시작 전에 설정창을 열지 않는다.
- 기존 데이터의 자동 전환 Modal을 없애고 원본 보관·선택 전환을 선택 옵션으로 옮긴다.
- adjustingId, 진행선 조정 메뉴, 조정 완료 버튼을 제거한다. 선택 상태는 핸들·옵션 노출만 담당한다.
- 본체/마커/양 끝 핸들 Hit Target을 분리하고 서로 겹칠 때 핸들·마커를 우선한다.
- 본체에는 32~44px Hit Area, 핸들·마커에는 44px Touch Area를 확보한다.
- 본체 드래그는 8px 이후 X/Y 축 고정, 끝 핸들·마커는 X축 이동만 허용한다.
- pointer capture를 사용하고 PDF Pan과 이벤트를 분리한다. 패널 활성화는 시작 시 한 번만 처리한다.
- 화면 중심 생성 좌표는 활성 패널의 보이는 페이지 영역을 페이지 상대 좌표로 변환해 계산한다.

산출물: 설정 없이 바로 움직일 수 있는 주선·참고선·마커·길이 핸들.

완료 기준:
- 새 PDF와 사진 페이지에서 시작 버튼 한 번으로 현재 화면에 선이 보이고 즉시 드래그된다.
- 마커가 없는 선도 본체 드래그와 옵션 접근이 된다.
- 선 내부 Gesture는 PDF를 Pan하지 않고 선 밖 Gesture는 기존 Pan을 유지한다.
- 대각선 입력도 선택된 축을 pointer up까지 유지하며 페이지·분할 경계를 넘지 않는다.

## Phase 2 — 드래그 임시 상태와 최종 저장

선행 조건: Phase 1.

- 본체·마커·핸들의 move는 시작 패널의 임시 Overlay 상태만 갱신한다.
- 일반 PageWork 저장 경로에 미완성 드래그 좌표를 전달하지 않는다. 중간에 다른 작업 저장이 발생해도 임시 좌표가 DB에 섞이지 않게 한다.
- pointer up에서 최종 PageWork를 한 번 반영하고 실행 취소 항목도 Gesture당 하나만 만든다.
- pointer cancel, capture 상실, 페이지·회전·보기 전환, 숨김 탭에서는 미완성 드래그를 취소하고 마지막 확정 좌표를 유지한다.
- opacity Slider도 같은 방식으로 Gesture당 최종 저장·실행 취소 하나를 만든다.
- 카운터와 진행선 확정 상태는 기존 단일 트랜잭션을 사용한다.

산출물: 임시 화면 상태와 확정 저장 상태의 분리.

완료 기준:
- 2초 드래그 중 DB 쓰기 0회, pointer up에 해당 작업 저장 1회.
- Undo 한 번으로 드래그 시작 위치로 돌아간다.
- 취소·패널 전환 후 잘못된 페이지에 저장되지 않는다.
- 좌표만 움직일 때 PDF.js 또는 사진 본문 렌더 요청 수가 늘지 않는다.

## Phase 3 — 직접 드래그로 카운터 연결

선행 조건: Phase 1~2.

- 옵션에 ‘카운터와 연결’을 넣고 필요한 경우 연결할 카운터만 선택한다.
- 기존 좌표 입력 Wizard와 페이지 두 번 탭 방식을 교체한다.
- Viewer 안의 작은 안내로 ‘현재 단에 맞추기’ → ‘다음 단에 맞추기’를 제공한다. 사용자는 같은 선을 직접 드래그하고 각 위치를 확인한다.
- 첫 위치는 희미한 Ghost Line으로 표시한다. 두 y 차이에서 간격·방향을 계산한다.
- 현재·+1·+2·+3 위치를 Ghost Line으로 Preview하고 ‘연결하기/다시 맞추기/취소’를 제공한다.
- 같은 위치, 너무 작은 간격, 페이지 밖 Preview는 연결 전에 안내한다. 페이지 끝에서는 clamp하며 다음 페이지로 이동하지 않는다.
- 연결 확정 때만 카운터 ID·간격·방향·현재 기준 단을 저장한다. 취소는 원래 선과 기존 연결 상태를 복원한다.
- ‘단 간격 다시 맞추기’도 같은 흐름을 사용한다.

산출물: 숫자·좌표 입력 없는 연결 Calibration.

완료 기준:
- 위→아래·아래→위 도안 모두 Preview와 실제 +1 위치가 일치한다.
- 연결 전에는 +1이 선 위치에 영향을 주지 않는다.
- Calibration 도중 카운터·페이지·회전 대상이 변경되면 혼합 좌표를 저장하지 않고 취소한다.

## Phase 4 — 카운터 이동·직접 보정·반복 정합성

선행 조건: Phase 3.

- 카운터 변경을 단 완료/−1, 숫자 직접 입력, 이력 복원, 설정 변경으로 구분한다.
- 간격 계산은 확정 위치와 그 위치의 기준 단을 한 쌍으로 관리한다. 이동 후 기준 단을 함께 갱신하거나 불변 기준점 계산을 사용하며 두 방식을 섞지 않는다.
- 대상 활성 주선만 +1/−1에 따라 이동하고, 관련 없는 페이지·카운터 그룹·참고선을 보존한다.
- +1로 다음 단이 바뀌면 경계 clamp로 위치가 같아도 마커를 초기화한다. 목표 완료로 같은 단에 머문 경우는 단 변경 여부로 판단한다.
- 연결선 직접 보정은 카운터 값을 바꾸지 않고 간격을 유지한다. 보정된 위치를 현재 단 기준점으로 삼는다.
- 숫자 직접 변경은 선 위치·마커를 유지하고 기준 단만 새 숫자로 맞춘다. 다음 +1부터 한 간격 이동한다.
- 기존 −1/이력 복원에서 저장된 주선·마커를 정확하게 복원한다. 회전별 좌표·마커 변경도 동등 비교에서 누락하지 않는다.
- 반복 영역이 명시된 경우만 마지막 줄→첫 줄로 돌아간다. 영역·반복 옵션이 없으면 페이지 경계에 멈춘다.

산출물: 일정 간격 이동과 안전한 숫자 보정·복원.

완료 기준:
- y=0.40, 간격=0.05에서 연속 +1 세 번은 0.45→0.50→0.55이고 누적 가속이 없다.
- 직접 y=0.61로 보정 후 +1은 0.66, currentRow는 보정 Gesture로 바뀌지 않는다.
- 42→68 직접 입력에서 y는 그대로이며 다음 +1만 한 간격 이동한다.
- 비활성 페이지·참고선·다른 카운터 그룹은 변경되지 않는다.
- 8단 반복은 명시 연결에서만 첫 줄로 돌아가며 RS/WS·보조 반복 갱신은 기존 카운터 로직을 따른다.

## Phase 5 — 옵션·집중 보기·저장 호환 마감

선행 조건: Phase 4.

- 옵션을 마커 표시/지우기, 집중 보기, 카운터 연결/해제, 간격 다시 맞추기, 참고선 추가, 표시 스타일, 삭제로 정리한다.
- 참고선은 항상 직접 이동 가능하고 카운터·Calibration·집중 보기 대상에서 제외하며 주선보다 약하게 표시한다.
- 집중 보기는 활성 패널의 SVG/CSS Dim만 사용한다. 구형선 호환 표시의 Canvas Blur 경로도 제거한다.
- 기존 페이지 상대 좌표·회전별 위치·원본 보관 필드를 재사용한다. 예시 타입을 맞추기 위해 기존 데이터 모델을 다시 만들지 않는다.
- 필요한 필드가 달라지는 경우에만 백업 버전 변경 여부를 결정하고 v1~v14 작업 파일 가져오기를 유지한다. 계획 단계에서 버전 상승을 미리 확정하지 않는다.
- DESIGN.md·Architecture.md·AGENTS.md의 이전 ADJUST 기준을 최종 구현 기준에 맞춰 갱신한다.

완료 기준:
- 저장 후 재실행·작업 파일 내보내기/가져오기에서 선·마커·연결·회전별 좌표가 복원된다.
- 기존선의 미선택 원본과 사용자 데이터가 보존된다.
- 새 페이지 최초 시작에는 설정·온보딩·전환 팝업이 없다.
- 집중 보기에서 Blur 필터와 본문 재렌더 호출이 없다.

## Phase 6 — 검증과 portable 전달

선행 조건: Phase 1~5.

- 단위·회귀 검증: 축 고정, clamp, Gesture 저장 횟수, Calibration 방향, 연속 이동, 직접 숫자 보정, 경계 마커 초기화, 회전별 값 비교, 그룹 이력 복원, 구형 백업.
- npm run typecheck, npm run lint, npm test, npm run build, npm run build:portable 실행.
- 생성된 portable/index.html을 기준으로 브라우저에서 PDF·사진, 확대·회전, 단일·분할 보기의 실제 클릭·드래그를 검증한다.
- 같은 페이지 양쪽 표시, 다른 페이지 양쪽 표시, Gesture 중 포인터가 Divider를 넘는 경우를 별도로 확인한다.
- PDF 렌더 요청과 저장 호출을 관찰해 ‘좌표 조작으로 본문 재렌더 없음’과 ‘move 중 DB 쓰기 없음’을 확인한다.
- Android 태블릿의 손가락·펜·스크롤 충돌은 실제 기기 검증 결과로 별도 기록한다.

## 리스크와 구현 시작점

- 우선순위가 높은 위험은 카운터 간격 계산의 누적, 다른 페이지 연결선의 동시 이동, 임시 좌표의 저장 유입이다.
- 같은 페이지 두 패널의 저장 선은 페이지 단위 공유를 기본으로 계획했다. 패널별 독립 저장이 필요하면 별도의 데이터 설계 변경이 필요하다.
- 기존 −1의 정확한 이력 조건은 유지한다. 모든 중간 시작 상태에서 −1을 새로 허용하는 범위는 이번 계획에 포함하지 않는다.
- 첫 작업은 ProgressLineOverlay의 조정 모드 제거와 본체/마커/끝 핸들 Gesture 분리다. Phase 1~2까지 먼저 완결해 직접 드래그와 저장 경계를 확인한 뒤 카운터 연결을 바꾼다.

- `ProgressLineOverlay`에서 본체 직접 이동, X축 마커·끝 핸들, 포인터 종료 때 단일 저장·Undo, 직접 Calibration Preview, 표시 스타일·집중 보기·참고선 메뉴를 구현했다. 시작 전 팝업과 `ADJUST` 모드를 제거했다.
